02 — ImplementationBuilding a RAG Pipeline with LangChain

Let's build a production-ready RAG system from scratch. We'll index a set of PDF documents, store embeddings in a vector database, and expose a question-answering chain.

📦
Prerequisites pip install langchain langchain-openai chromadb pypdf tiktoken

Step 1 — Document Ingestion & Chunking

rag_ingest.py 
from langchain.document_loaders import PyPDFDirectoryLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain.vectorstores import Chroma

# ── Load documents from a directory of PDFs ──────────────────
loader = PyPDFDirectoryLoader("./docs")
documents = loader.load()
print(f"Loaded {len(documents)} pages from {len(set(d.metadata['source'] for d in documents))} files")

# ── Chunk into overlapping segments ──────────────────────────
splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,       # ~750 tokens per chunk
    chunk_overlap=200,     # overlap prevents context loss at boundaries
    length_function=len,
    add_start_index=True,
)
chunks = splitter.split_documents(documents)
print(f"Split into {len(chunks)} chunks")

# ── Embed and store in ChromaDB ───────────────────────────────
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db",
    collection_name="rag_docs",
)
vectorstore.persist()
print("✅ Vector store built and persisted.")

Step 2 — The Retrieval Chain

rag_chain.py 
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain.vectorstores import Chroma
from langchain.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# ── Load existing vector store ────────────────────────────────
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings,
    collection_name="rag_docs",
)

# ── Configure retriever ───────────────────────────────────────
retriever = vectorstore.as_retriever(
    search_type="mmr",           # Max Marginal Relevance: diverse results
    search_kwargs={
        "k": 5,                 # retrieve top 5 chunks
        "fetch_k": 20,           # candidate pool for MMR
        "lambda_mult": 0.7,     # diversity weight
    }
)

# ── Prompt template ───────────────────────────────────────────
PROMPT_TEMPLATE = """You are a helpful AI assistant. Answer the question
based ONLY on the following context. If the context doesn't contain
the answer, say "I don't have enough information."

Context:
{context}

Question: {question}

Provide a clear, accurate answer with specific details from the context.
Cite relevant sections when useful."""

prompt = ChatPromptTemplate.from_template(PROMPT_TEMPLATE)
llm = ChatOpenAI(model="gpt-4o", temperature=0)

# ── Build the chain using LCEL ────────────────────────────────
def format_docs(docs):
    return "\n\n---\n\n".join(
        f"[Source: {d.metadata.get('source','?')}, p.{d.metadata.get('page','?')}]\n{d.page_content}"
        for d in docs
    )

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)

# ── Query it ──────────────────────────────────────────────────
query = "What are the key risks mentioned in the annual report?"
answer = rag_chain.invoke(query)
print(answer)

Step 3 — Advanced: Hybrid Search + Reranking

⚡
Production tip Pure vector search misses exact keyword matches. Hybrid search combines dense (semantic) + sparse (BM25) retrieval for best results.
hybrid_rag.py 
from langchain.retrievers import BM25Retriever, EnsembleRetriever
from langchain.retrievers.document_compressors import CrossEncoderReranker
from langchain.retrievers import ContextualCompressionRetriever
from langchain_community.cross_encoders import HuggingFaceCrossEncoder

# ── Sparse retriever (keyword-based BM25) ─────────────────────
bm25_retriever = BM25Retriever.from_documents(chunks)
bm25_retriever.k = 5

# ── Dense retriever (semantic) ────────────────────────────────
dense_retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

# ── Hybrid: 40% BM25 + 60% dense ─────────────────────────────
ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, dense_retriever],
    weights=[0.4, 0.6]
)

# ── Reranker: score with cross-encoder for final precision ────
cross_encoder = HuggingFaceCrossEncoder(
    model_name="cross-encoder/ms-marco-MiniLM-L-6-v2"
)
compressor = CrossEncoderReranker(model=cross_encoder, top_n=3)

final_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=ensemble_retriever,
)
The gap between a demo RAG and a production RAG is not the LLM — it's the retriever. Invest there first.

04 — What's NextThe Future of RAG

We're still in early innings. The RAG landscape is evolving at a pace that makes 2023's techniques feel prehistoric.

Agentic RAG

The retriever becomes an agent. It decides what to retrieve, when to retrieve it, and can issue multiple queries iteratively.

Multimodal RAG

Retrieve and reason over images, audio, video, and structured tables — not just text. GPT-4V and Gemini 1.5 are early previews.

Self-Improving RAG

Systems that learn from user feedback to improve retrieval strategies autonomously, closing the loop between usage and accuracy.

The direction is clear: RAG is converging with agentic architectures. Tools like LangGraph and AutoGen are building systems where the retrieval step is just one node in a larger reasoning graph. The model decides when it needs more information, what to search for, and how to synthesize multi-step retrieved context.

05 — The PitfallsWhat Nobody Tells You About RAG

RAG sounds simple. In practice, every step is a failure mode.

Stage Common Failure Fix
Chunking Chunks split mid-sentence, losing context Use semantic chunking or larger overlap
Embedding Generic embeddings miss domain terminology Fine-tune embeddings on your domain data
Retrieval Top-k returns irrelevant chunks Add reranking with cross-encoders
Prompt LLM ignores retrieved context, uses prior knowledge Stronger system prompt: "ONLY use the context below"
Generation Answer correct but source not cited Instruct model to cite chunk IDs in output
🎯
Evaluation is non-negotiable Use RAGAS (Retrieval-Augmented Generation Assessment) to measure faithfulness, answer relevancy, context recall, and context precision on a held-out test set before shipping to production.
